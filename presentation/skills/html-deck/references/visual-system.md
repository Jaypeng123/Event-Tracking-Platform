# 視覺系統：design read、色彩、字體、版型、元件

原則：**主色從使用者的素材來，結構變化從版型輪替來，質感從克制來。** 不要用「加光暈、加漸層、加卡片」製造高級感。

## 1. Design read（動工前寫一段，給使用者確認）

```text
這是一份 <類型>，給 <受眾>，在 <場景> 使用。
方向：<一個明確的語氣：例如「冷靜的編輯感」「溫暖手作」「工程藍圖」「大膽海報」>；
色彩策略：<克制／投入／完整／浸潤>，主色取自 <品牌／素材>；
全場高峰：<哪一頁>；唯一記憶點：<一個手法，全場只用一次>。
```

- **場景決定深淺色**：暗場投影 → 深色；有燈的會議室、螢幕分享、寄送閱讀 → 淺色通常更清楚。寫不出場景就是還沒想清楚。決定後整份鎖定，不每頁換主題（只允許一次刻意的章節反轉）。
- **語氣要選一個極端**並說得出理由；不要「乾淨現代」這種所有人都適用的詞。
- **反射檢查**：只看主題類別就能猜到你的配色與風格（例如「AI 產品＝深色＋紫藍光」「餐飲＝米色＋棕」），就是第一反應，要重想。
- **記憶點**（second-read moment）全場一個：例如一個超大數字、一次材質切換、一個貫穿的視覺隱喻。

## 2. 色彩

**先選策略，再選顏色：**

| 策略 | 做法 | 適合 |
| --- | --- | --- |
| 克制 Restrained | 中性色＋一個強調色，強調色面積 ≤ 10% | 內部報告、技術分享、研究、多數商務場合 |
| 投入 Committed | 一個飽和色佔 30–60% 畫面 | 品牌感強的發表、提案封面與章節頁 |
| 完整 Full palette | 3–4 個有名字的角色色，各有用途 | 教學、多類別資料、工作坊分組 |
| 浸潤 Drenched | 整個畫面就是那個顏色 | 封面、章節頁、金句頁的一次性使用 |

**Tokens（全部寫在 `:root`，頁面裡不寫裸色碼）**

| 類別 | 規則 |
| --- | --- |
| 背景 | 3 階 `--bg-0/1/2`；不用純 `#000`／`#fff`；中性色往主色相偏 0.005–0.015 chroma（OKLCH）。 |
| 強調色 | 一個，只給 1–2 個元素（重點字、核心結論、目前步驟、主要按鈕）。飽和度不要拉滿。 |
| 語意色 | 最多 3 個（正向／警示／負向），只用於狀態、比較、分類；同時配圖示或文字，不只靠顏色。 |
| 文字 | 主文字、次文字、註記三階。內文對比 ≥ 4.5:1；投影會洗淡顏色，關鍵文字盡量 ≥ 7:1。不要用淺灰「營造高級感」。有色背景上的次文字用同色相的深淺，不用灰。 |
| 圓角 | 一套：大容器 12–16px、小元件 6–10px；巢狀時外圈 = 內圈 + 內距。避免 ≥ 24px 的卡片圓角。 |
| 陰影 | 只表達高度；細邊框或小而淡的有色陰影二擇一，不要「1px 邊框＋大模糊陰影」。 |
| 間距 | 4/8 倍數；組間距 ≥ 組內間距的 2 倍；舞台安全邊距 80–110px，標題位置每頁一致。 |

- 品牌色存在就以它為主；從 PPTX、Figma、官網取色。沒有品牌色時，從主題的實物或情境找一個色相，而不是從「這類產品常用什麼色」找。
- 可用的漸層：同色相明度漸層、暈影、極淡 noise。避免：紫→藍、粉→橘、彩虹 mesh、霓虹光暈、漸層文字。
- 避免把米色／紙色當預設背景（AI 生成的常見預設）；要暖感就用強調色、圖片與字體去帶。
- 圖片外框：淺色主題 `outline:1px solid oklch(0 0 0/.1)`、深色 `oklch(1 0 0/.1)`，`outline-offset:-1px`。

## 3. 字體與字級

- **字體**：中文用系統字堆疊 `"PingFang TC","Noto Sans TC","Microsoft JhengHei",system-ui`（離線可用）。Latin 不預設 Inter／Roboto／Arial；需要個性時選一款，單檔交付要 subset 後 base64 內嵌。家族 ≤ 2（＋等寬字給程式碼與數據）。配對要有對比（襯線＋無襯線，或同家族多字重），不要兩款相似的無襯線。
- **強調**用字重或強調色；標題不用斜體（中文沒有真斜體），標題中不混入另一個字體家族的單字。
- **字級用比例算，不要一個一個猜**：以內文為基準，選比例後往上推 4–5 階。

| 比例 | 性格 | 適合 |
| --- | --- | --- |
| 1.2（小三度） | 穩重 | 資訊多的報告、教學 |
| 1.333（完全四度） | 層級明顯 | 多數簡報的預設 |
| 1.5（完全五度） | 戲劇性 | 發表、提案封面 |
| 1.618（黃金比） | 海報感 | 只放大字的封面與金句頁 |

- **行高隨字級遞減**：約 `clamp(1.5 − 0.06×階數, 1.15, 1.6)`；超過 120px 的字收到 1.05。中文內文另外放寬到 1.7–1.8。
- **1600×900 舞台參考值**（投影時舞台會整體縮放）：

| 角色 | 字級 | 行高 | 備註 |
| --- | --- | --- | --- |
| 封面／章節／金句 | 72–96px | 1.05–1.15 | ≤ 2 行 |
| 頁標題 | 44–52px | 1.2–1.3 | ≤ 2 行；`text-wrap: balance` |
| 小標題 | 24–30px | 1.35 | |
| 內文 | 19–24px | 1.7–1.8 | `text-wrap: pretty`；每行 ≤ 約 36 個中文字（英文 45–75 字元） |
| 註記／圖說 | 15–16px | 1.6 | 不要更小；字重 ≥ 400 |
| 標籤 | 13–14px | 1 | 只給 Latin 大寫標籤，字距 .08–.16em |

- 中文**不加負字距**；負字距只給 Latin 大標（-0.01 到 -0.03em，不低於 -0.04em）。
- 會變動或要對齊的數字用 `font-variant-numeric: tabular-nums`。
- **孤字**：最後一行只剩 1–2 個字就改寫、調寬或手動斷行，不要靠縮字級。
- **標點懸掛**：行首「『（用 `margin-left:-.5em` 讓文字左緣對齊。
- 同一排並列的標題長度接近或固定高度；內文用 `min-height` 對齊；按鈕、結論等收尾元素對齊到同一條底線。

## 4. 版型家族、構圖錨點、背景模式

逐頁表中每頁標記一個**版型家族**、一個**構圖錨點**、一個**背景模式**。

| 版型家族 | 用途 |
| --- | --- |
| Statement | 一句大字（封面、章節、金句、轉折） |
| Split | 文字與視覺分欄（40/60、50/50、60/40） |
| Grid | 2–4 個並列項目（原因、選項、步驟、功能） |
| Full-bleed | 一張大圖、影片或內嵌網站佔滿 |
| Evidence | 圖表、數據、表格 |
| Compare | 比較表、before/after、A vs B |
| Flow | 步驟、流程、時間軸、互動說明 |
| Dialogue | 引言、訪談摘錄、對話、提示詞與回覆 |
| Quiet | 一個數字、一句話或一張圖，留白很多 |

- **構圖錨點**：置中、左上起、左下壓圖、右三分之一、低置中、偏離格線、圖即畫布。「左文右圖」最容易氾濫，不要預設也不要連用。
- **背景模式**：純色＋內嵌素材、滿版圖＋局部遮罩、側邊圖、色塊雙聯、暈影＋物件、極淡質感、同色相漸層。

**輪替規則**
- 同一版型家族、同一構圖錨點不連續超過 2 頁；同一背景模式不連續超過 3 頁。
- 整份至少 4 種家族；非極簡風格至少 1 頁 Full-bleed 與 1 頁 Quiet。
- 三張一樣的卡片連排、卡片內再放卡片是最典型的 AI 版面：能用列表、表格、流程、大數字就不要硬做卡片；卡片數量依內容決定。
- 大格網格（bento）格數要等於內容數，不留空格。
- 超過 5 個項目就換元件（分組、表格、兩欄），不要一長串條列。

## 5. 元件規格（範例 CSS 見 `assets/template.html`）

- **章節標籤／eyebrow**：只在簡報真的有章節時用，作用是讓觀眾知道自己在哪；整份統一一種寫法，不每頁都放不同的小標，不捏造「SECTION 01」「V2.0 BETA」這類假中繼資料。
- **卡片**：圖示（一致線條粗細）＋標題＋1–2 句。卡片變高、中段空白時，用大型圖示徽章或圖片填滿，不要拉伸文字或留空洞。
- **核心結論框**：只給真正的 takeaway，一份 3–6 個；太多就沒有重點。不要用粗左邊框當強調。
- **引言／對話**：照原文、標明出處與身分；最多 3 行，長的放備註。對話用左右氣泡區分角色。
- **截圖框**：先裁掉瀏覽器、作業系統外框與空白邊；只用細外框＋圓角＋淡陰影；可點擊放大（`data-zoom`）；多張可疊放切換。
- **手機畫面**：可放進一致的簡潔裝置框（同比例、同大小、四周留白均等、不碰畫面邊緣），內容才是主角；不要畫假的狀態列圖示。
- **比較表**：第一欄是比較維度；用白話與比喻，寫具體差異（「每月少 3 小時人工對帳」而不是「效率更好」）；數字欄靠右並用等寬數字。
- **步驟同步檢視器**：左邊步驟、右邊對應畫面，點擊或自動輪播切換，取代一頁塞多張截圖。
- **互動說明元件**：用原生前端做小模擬（切換、計數、流程亮燈）解釋機制；每個互動都要有明確用途。
- **狀態頁**：講產品或設計時，空狀態、載入、錯誤、權限不足等非理想狀態常是最有說服力的一頁。
- **圖示**：一套圖示庫、一種線條粗細（配一般字重 1.5、粗體 2）、`currentColor`；不要自己手畫圖示路徑，不用 emoji 當圖示，避免「火箭＝上線、盾牌＝安全」這類陳腔濫調。

## 6. 背景與氛圍（克制）

- 背景微互動最多一種：游標聚光、極淡質感、或與主題相關的生成圖形。裝飾性格線、斜紋、光球不要當預設。
- 低對比、放在文字後面、`pointer-events:none`；`prefers-reduced-motion` 時停止；不要做滿版持續移動的背景或約 5 秒一循環的緩慢擺動（容易不舒服）。
- 生成式背景固定 seed，排練和正式看到的一樣；不在畫面上的頁面要暫停。
- 較強的背景只放在封面、章節、結尾；內容頁讓位給內容。
- 文字壓在圖片上時只在文字區域加遮罩或漸層，不整張壓暗。

## 7. AI 味清單（出現就修）

- 每頁都有小型大寫 eyebrow；裝飾性「01 / 06」編號；假版本號、假座標、假狀態點
- 紫藍漸層、漸層文字、霓虹光暈、毛玻璃疊毛玻璃、到處都是光球與格線背景
- 三張一樣的卡片、卡片套卡片、每頁都置中、每頁都左文右圖
- 大數字＋小標籤＋三個統計的「英雄數據」模板（沒有真實數據時）
- 編造的數據（+47%、10x、99.9%）、假引言、假客戶 logo、假品牌名（Acme、Nexus）
- 文案詞：賦能、無縫、顛覆、打造極致、全方位、一站式、引領未來；英文 elevate、seamless、unleash、next-gen
- 每個元素 hover 都放大、每個區塊同一種淡入、永遠在跳動的指示點
- 文字烘焙進圖片（無法修改、無法被讀出）
- 手繪假瀏覽器列、假程式碼視窗、用 div 拼出的假產品畫面
- 結尾只有「Thank you」淡出
