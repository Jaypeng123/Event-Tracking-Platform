# 投影片視覺：舞台、層次、每種頁面怎麼構圖

`visual-system.md` 定的是規則（色彩、字級、tokens）；這份講**畫面本身**：一頁投影片的視覺要怎麼組、每種頁面有哪些構圖可選、整份簡報的節奏怎麼排。

## 1. 舞台與網格

- 舞台 1600×900；安全邊距左右 92px、上 64px、下 72px（底部留給頁碼與進度條）。
- 12 欄網格：欄寬約 100px、欄距 24px。常用切分：6/6、5/7、4/8、3/9、全幅。
- **標題錨點固定**：內容頁的標題永遠在同一個 x、y（例如 x=92、y=64 起），換頁時眼睛不用重新找。章節頁、封面、金句頁可以打破。
- 底部 72px 是 HUD 區（頁碼、進度條、導覽按鈕），內容不要放進去。
- 一頁的內容區高度大約 900 − 64 − 標題區 − 72 ≈ 600px；放不下就拆頁。

## 2. 一頁的三層

每頁都由三層組成，越上層越少、越亮、越清楚：

| 層 | 內容 | 視覺處理 |
| --- | --- | --- |
| 背景層 | 底色、漸層、氛圍互動（聚光、粒子、質感） | 低對比、不搶眼、`pointer-events:none` |
| 結構層 | 卡片、表格、截圖框、對話框、流程節點 | 淡底色或細外框，彼此對齊 |
| 焦點層 | 這頁要觀眾第一眼看的東西（一個） | 最大、最亮、或唯一用強調色 |

**每頁只有一個焦點**。瞇眼看投影片，第一眼看到的應該就是標題要講的那件事；如果第一眼看到的是背景特效或裝飾，就要降低背景。

## 3. 強調手法（選一到兩種，不要全上）

| 手法 | 做法 | 適合 |
| --- | --- | --- |
| 尺寸跳級 | 重點字比周圍大 2 階以上 | 數字、金句 |
| 強調色單字 | 標題中一個詞用強調色 | 每頁標題的關鍵詞 |
| 底線畫出 | 進場時在關鍵詞下畫出一條線（`scaleX` 0→1） | 封面、結論 |
| 框選標註 | 在截圖上框出重點區域＋短標籤 | 截圖證據 |
| 其他變暗 | 非重點元素降到 40–60% 不透明 | 比較、步驟中的目前項 |
| 實心反白 | 重點那張卡片／那一列用強調色底 | 推薦方案、選定答案 |
| 留白隔離 | 重點四周留大片空白 | Quiet 頁 |

強調色只給焦點；同一頁出現三個強調色元素，就等於沒有強調。

## 4. 深度與質感

- **深度來源**：細外框＋淡底色（平面感）、小陰影（輕微浮起）、重疊與錯位（疊放截圖、傾斜產品圖）、前後景模糊。整份選一種主要深度語言。
- 深色主題：卡片用 3–7% 白色疊加的半透明底＋細亮邊；陰影要深而大才看得到。
- 淺色主題：卡片用白底＋1px 淡邊或極淡陰影；不要灰底灰邊灰字全混在一起。
- 圖片是最強的質感來源：真實截圖、產品照、團隊照勝過任何裝飾。
- 一份簡報的圓角、陰影、外框粗細要一致；元件換頁後看起來要像同一套。

## 5. 各類頁面的構圖選項

### 封面（全場第一印象）
| 構圖 | 畫面 | 適合 |
| --- | --- | --- |
| 左文右物 | 左 5–6 欄：類型標籤 → 大標（2 行內）→ 一句導言 → 講者與場合；右側：產品畫面以 3D 輕微傾斜呈現，外圍淡色同心環，2–3 個小資訊籌碼漂浮 | 產品、工具、設計分享 |
| 全幅主視覺 | 一張滿版照片或生成圖，標題放在圖片乾淨的區域，只在文字下方加漸層遮罩 | 發表、品牌、活動 |
| 純字海報 | 超大標題佔畫面 60% 以上，其餘留白，一個強調色詞 | 演講、觀點、研究 |
| 數字開場 | 一個巨大的真實數字＋一句它代表什麼 | 報告、提案（必須是真數據） |

封面右下或底部放講者、日期、場合；不要放公司 logo 牆。

### 議程／總覽
- 3–5 個章節做成橫向軌道：每個章節一張卡（編號、名稱、一句說明），上方一條細線串起來，可點擊直接跳到該章節。
- 章節超過 5 個就改成兩欄列表。

### 章節頁
| 構圖 | 畫面 |
| --- | --- |
| 大字鏤空 | 章節英文或關鍵字用超大鏤空字（只有外框），下方一句這段要回答的問題；右側一個大數字或圖示，外圍環繞細環 |
| 色塊浸潤 | 整頁換成主色底，白色大字；全場只用一兩次 |
| 安靜過場 | 只有一行字與大量留白 |

章節頁下方可放章節導覽膠囊（目前章節反白），讓觀眾知道全貌與位置。

### 重點／原因（Grid）
- 2–4 張卡片等寬並排，卡片頂部對齊；內容少時讓卡片變高，中段放大圖示徽章，文字壓到底部。
- 4 個以上考慮 2×2；項目長短不一時改成列表。
- 編號只在真的有順序時使用。

### 證據／數據（Evidence）
- 標題寫結論；圖表佔 2/3，解讀文字佔 1/3；或圖表佔滿整頁。
- 要觀眾看的那個數值用強調色，其他用中性色；來源寫在左下角小字。
- 單一數字頁：數字 160–240px，旁邊一句說明，其他都不要。

### 截圖展示
| 構圖 | 畫面 |
| --- | --- |
| 大圖＋說明 | 截圖佔 7–8 欄，右側 3 點說明，截圖可點擊放大 |
| 疊放 | 兩張截圖前後錯位疊放，點擊交換前後，適合「前後版本」「兩個畫面」 |
| 步驟同步 | 左側步驟列表、右側畫面，目前步驟亮起、畫面交叉淡入，可自動輪播 |
| 標註 | 截圖上框出重點、拉一個短標籤；其餘區域可微暗 |
| 裝置框 | 手機畫面放進一致的裝置框，2–3 支並排時大小與間距相同 |

截圖一律先裁掉瀏覽器與系統外框，用細邊與陰影把它「放」在舞台上。

### 流程（Flow）
- 3–5 步橫向排列，步驟之間用箭頭或細線；要強調「卡住的那一步」就給它警示色底與標籤。
- 垂直流程（節點＋連接線）適合講資料或請求怎麼流動，連接線上可以有光點流動表示方向。
- 超過 5 步就分兩頁或改成時間軸。

### 比較（Compare）
- 表格：第一欄是維度，欄位標題可帶名稱＋一句暱稱或比喻；推薦的那一欄用淡強調色底，結論列加粗。
- Before／After：左右兩張卡，中間一個箭頭圓鈕；Before 降低不透明度，After 用強調色外框。
- 選項對照：每個選項一張卡，列出適合／不適合，推薦的那張實心反白。

### 對話／引言（Dialogue）
- 對話視窗：頂部一條標題列（對象名稱），內文左右氣泡區分角色，頭像用字母或圖示；需要指出問題時，在氣泡內把那段文字用警示色底標記。
- 單一引言：大字引言（≤ 3 行）＋出處；可以搭配人物照片。

### Demo／內嵌網站
- 進入 Demo 頁時整個舞台被全螢幕網站取代，底部浮著一條控制列（返回簡報、重新整理、新分頁開啟），閒置時自動變淡。
- 載入期間顯示品牌色的載入畫面與一句「正在開啟 …」，超過約 9 秒顯示備案按鈕。

### 核心結論／金句
- 一句大字（64–80px）＋一句副標說明「為什麼」；底部可放一排 3–5 個關鍵詞依序亮起，串成一句話。
- 核心結論框只放一句話，全場 3–6 個。

### 結尾與 Q&A
- 結尾回到開場的問題並給答案與一個行動；Q&A 頁簡單一個大字與聯絡方式，不要「Thank you」淡出。

## 6. 整份簡報的節奏

- 依逐頁表的「感受曲線」安排強弱：章節頁、金句頁、Quiet 頁是「安靜」；Demo、高峰、證據是「強」。強與安靜交替，不要連續 4 頁都是密集內容。
- 高峰頁給最大的視覺變化（全幅、Demo、浸潤色塊），前一頁刻意安靜。
- 同類頁面用同一種構圖（例如所有「關卡」頁都用同一個框架），讓觀眾辨識出段落；不同類頁面之間才換構圖。
- 視覺手法跟敘事走：一個貫穿全場的隱喻（例如「訊號／節點」「路線圖」「實驗室」）可以同時出現在背景、章節頁與圖示選擇上，只要不搶內容。
- 做完先看縮圖總覽：一眼看過去要能分出段落、找到高峰、看到強弱交替。

## 7. 視覺自我檢查

- [ ] 每頁瞇眼看只有一個焦點，且就是標題說的那件事
- [ ] 內容頁標題位置一致；左右邊距一致
- [ ] 強調色只出現在焦點上
- [ ] 同一排元素頂部或底部對齊；並列卡片內的標題、說明、結尾元素各自對齊
- [ ] 沒有空洞（卡片中段、頁面下半部大片無意義的空白）也沒有擁擠（內容貼到 HUD 區）
- [ ] 截圖都裁過外框、比例一致
- [ ] 縮圖總覽看得出節奏與高峰
