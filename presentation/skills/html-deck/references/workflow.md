# 內容流程：需求表 → 簡報類型 → 六步驟 → 確認點

這份檔案管**內容與結構**。視覺、動態、實作看其他 reference。

## 0. 簡報需求表（開工前填，未定欄位寫「待討論」）

```text
主題：
目的（說服／告知／教學／對齊／募資／求回饋）：
受眾（角色、背景、對主題熟悉程度、他們在意什麼）：
希望受眾記住的一句話：
希望受眾採取的行動（一個）：
簡報類型（見下表）：
使用情境（暗場投影／有燈會議室／線上螢幕分享／寄送閱讀／作品集）：
報告時間（含不含 Q&A）／預計頁數：
品牌色、字體、既有模板或過去的簡報：
現有素材與來源（文件、PPTX、PDF、截圖、網址、Figma、數據）：
必須包含／必須刪掉的內容：
是否嵌入網站或可操作 Demo：
其他限制（離線、單一檔案、保密資訊、公司規範）：
```

- 使用者已給素材時，從素材自動填表，只問會改變方向的缺口。
- 使用者說「直接做」「你決定」：寫一句推論（「我理解成：給 X 的 Y 簡報，在 Z 場合，主張是 W」），標明是推論，然後繼續。不要假裝是使用者說的。
- 「乾淨現代」不是風格；請對方給 3–5 個形容詞或一個參考（電影、雜誌、品牌，不限網站）。

## 1. 選簡報類型與骨架

先決定類型，再套骨架；骨架是起點，可以刪減重排，但「主張 → 證據 → 結論與行動」與唯一高峰要保留。

| 類型 | 骨架 | 高峰通常是 |
| --- | --- | --- |
| 設計分享／案例分享 | 主張 → 背景與問題 → 為什麼值得做 → 做了什麼（成品或 Demo）→ 過程中的關卡（每關：遇到什麼 → 怎麼處理 → 結果與教訓）→ 帶走什麼 → 想要的回饋 → Q&A | 成品展示或 Demo |
| 提案／募資 | 鉤子 → 問題與代價 → 為什麼是現在 → 解法 → 如何運作 → 證據（使用者、數據、試點）→ 商業模式或成本 → 團隊 → 請求（要什麼、多少、何時） | 解法第一次出現或證據頁 |
| 產品發表 | 情境 → 痛點 → 揭曉 → 三個關鍵能力（各配實際畫面）→ 價格與上市 → 行動 | 揭曉頁 |
| 技術分享 | 要解的問題 → 限制與目標 → 方案比較 → 架構 → 關鍵實作 → 成效（基準數據）→ 坑與教訓 → 下一步 | 架構或成效頁 |
| 教學／課程 | 學完能做到什麼 → 先備知識 → 概念 1（解釋 → 範例 → 小練習）→ 概念 2… → 總整理 → 練習或作業 → 延伸資源 | 第一個「原來如此」的範例 |
| 工作坊 | 目標與產出 → 議程與時間 → 規則 → 每個活動一頁（說明、時間、產出格式）→ 休息 → 收斂 → 下一步與負責人 | 主要活動開始 |
| 成果報告／週報 | 一句結論 → 關鍵指標（對比目標）→ 完成事項 → 風險與阻礙 → 需要的決策或支援 → 下期計畫 | 需要決策的那頁 |
| 研究報告 | 研究問題 → 方法與樣本 → 3–5 個發現（每個：發現 → 證據 → 意涵）→ 建議 → 限制 | 最反直覺的發現 |
| 作品集面試 | 我是誰（一句）→ 2–3 個案例（各：背景 → 我的角色 → 問題 → 選項 → 決策 → 成果 → 反思）→ 我怎麼工作 → Q&A | 第一個案例的決策頁 |

**通用節拍法**（類型不好歸時用）：認同（他們看到自己的處境）→ 張力（代價被說清楚）→ 轉折（改變的東西）→ 實證（為什麼成立）→ 選擇（可以怎麼做）→ 承諾（一個行動）。不服務任何節拍的頁面直接刪。

## 2. 六步驟

| 步驟 | 工作 | 產出 | 要停下來給使用者看嗎 |
| --- | --- | --- | --- |
| 01 | 簡報藍圖 | 目的、受眾、一句主張、類型與骨架 | 是（方向） |
| 02 | 逐頁結構 | 逐頁表：標題／目的／核心訊息／銜接／版型家族／時間 | 是（大綱） |
| 03 | 故事線 | 開場鉤子、轉場、情緒曲線、唯一高峰、結尾行動 | 併入 02 |
| 04 | 視覺指引 | design read、tokens、逐頁版型分配 | 做 2–3 頁樣張確認 |
| 05 | 逐頁完整內容 | 標題、一句結論、重點、建議視覺、來源、講者備註、待補 | 否，直接做進 HTML |
| 06 | 精簡 | 原本問題／修改後／原因；拆頁或合併建議 | 交付時附上 |

大綱錯了要重做全部，風格錯了要重做全部樣式，所以這兩個確認點不要省；其他可以合併。

### 02 逐頁結構

| 頁 | 標題（直接講結論） | 該頁目的 | 核心訊息 | 銜接 | 版型家族 | 時間 |
| --- | --- | --- | --- | --- | --- | --- |

- 每頁只有一個用途；兩頁講同一件事就合併，一頁講兩件事就拆。
- 「結果」與「問題」分開：先讓觀眾看到結果，下一頁再講卡在哪。
- 時間：每頁約 1–2 分鐘；Demo、活動另計；總時間再加 20–30% 緩衝。

### 03 故事線
- 每頁寫一個感受詞（好奇、困惑、緊張、鬆一口氣、篤定）。相鄰兩頁不要同感受又同版型，否則其中一頁是填充。
- 全場只有一個高峰，給它最大的視覺變化；高峰前一頁要安靜。
- 開場在 30 秒內說出這場要回答的問題；結尾回到同一個問題並給出行動。
- 設計分享、研究、提案類可以加一頁「我想要的回饋」：說明現在在哪個階段、想聽哪方面的意見、哪些不在範圍內。

### 05 完整內容
```text
頁碼／標題／一句核心結論／投影片重點（≤3–5 點，能少就少）／建議視覺／數據與來源／講者備註／待補資料
```
- 投影片上的字是觀眾讀的，備註是講者說的，兩者不要重複。
- 引用使用者給的原文（訪談、提示詞、客戶回饋）時照原文，可以摘錄但標明。

### 06 精簡
對每句話問：刪掉它，觀眾會少懂什麼？答不出來就刪。保留必要的條件、限制與證據。

## 3. 誠實規則（全程適用）
- 數據、案例、引用、logo、客戶名稱要有來源；沒有就標「待補資料」，絕不捏造。
- 沒有量化成果就只寫質性成果，並明講尚無數據；不要編「提升 47%」「10 倍速」。
- 示意資料、Demo 假資料要在畫面或備註標明。
- 不捏造使用者說過的話、評語或截圖內容；推論要標為推論。
- 把使用者的文件當素材而不是逐字稿：要濃縮成投影片語言；但使用者要求保留原文時照做。

## 4. 交付前內容檢查
- [ ] 目的、受眾、主張從頭到尾一致
- [ ] 每頁標題本身就能傳達重點
- [ ] 圖表標籤、單位、數據、來源正確
- [ ] 沒有遺留方括號、待填欄位、lorem、假品牌名
- [ ] 結尾有明確結論與一個行動
- [ ] 照備註試講一遍，總時間符合限制
