# 圖表、流程圖與數據頁

> zip 中列出的 Data Visualization skill 沒有附檔案；本頁整理自 diagram-design、pptx-presentations、imagegen-frontend-web、better-typography 與 UI 審查類 skill 的相關規則。

## 1. 先問要不要畫

- 一個 3 欄表格就能說清楚 → 用表格。
- 一句話就能說清楚 → 寫那句話，不要畫只有一個形狀的「圖」。
- 列舉項目 → 列表或卡片，不是圖。
- 只有屬性改變的 before/after → 比較表；結構改變 → 前後對照圖。
- 只有在「看圖比讀文字學得更多」時才畫。

**最好的修改通常是刪除**：兩個總是一起出現的節點合成一個；從版面就看得出關係的線就刪掉；顏色或形狀已經表達的標籤就刪掉。

## 2. 選類型

| 要表達 | 用 |
| --- | --- |
| 有分支的決策 | 流程圖 |
| 依時間的事件 | 時間軸 |
| 跨角色的流程與交接 | 泳道圖 |
| 元件與連線 | 架構圖 |
| 狀態與轉換 | 狀態圖 |
| 使用者在各階段做什麼、感受如何 | 使用者旅程 |
| 前台與後台、可見與不可見 | 服務藍圖 |
| 兩個軸向的定位或優先順序 | 2×2 象限 |
| 層級包含 | 巢狀圖／樹狀圖 |
| 轉換漏斗 | 漏斗 |
| 類別間數量比較 | 長條圖（橫向放長標籤） |
| 趨勢 | 折線圖；只有兩個時間點用斜率圖 |
| 起點到終點的增減組成 | 瀑布圖 |
| 部分佔整體且比例就是重點 | 樹狀圖（treemap）；類別 ≤ 4 才考慮圓餅 |
| 兩變數關係 | 散佈圖 |
| 一個數字就是重點 | 大數字頁（Quiet 版型），不要做成圖 |

## 3. 複雜度上限（每張圖）

| 項目 | 上限 |
| --- | --- |
| 節點 | 9（超過就拆成總覽＋細節兩頁） |
| 連線 | 12 |
| 強調色元素 | 2 |
| 註解 | 2 |
| 資料系列 | 4–5 |
| 動畫步驟 | 8 |

密度目標大約 4/10：技術上完整，但不需要說明書。

## 4. 畫法規則

- 強調色只給 1–2 個焦點元素（主要路徑、目前步驟、要比較的那一欄）；其他用主文字、次文字、中性色。
- 連線用水平垂直的折線（轉角小圓角），不畫斜線；平行線至少錯開 12px；同一邊的多條線各自分開接點。
- 線上的標籤要有不透明底，與線保持 6–10px 間距；不要用直排文字。
- 線先畫、節點後畫，讓線在節點下面；線不要穿過不相干的節點。
- 圖例放在下方一排，只列有用到的類型。
- 節點名稱用一般字體，等寬字只給埠號、指令、網址等技術內容。
- 節點不要每個都一樣，用填色、外框、圖示區分類型；不加陰影、圓角不大（6–10px）。
- 結構幾何對齊 4px 格線。
- SVG 加 `role="img"` 與 `<title>`／`<desc>`，裝飾性的加 `aria-hidden="true"`。

## 5. 數據頁

- **標題寫結論**：「Q3 退貨率比目標高 2 倍」，不是「退貨率趨勢」。
- **圖表與文字並排**：標題橫跨全寬，下方一欄文字、一欄圖表；或讓圖表佔滿整頁。不要把圖表壓在文字下方的單欄裡。
- 每張圖只講一件事；要比較的那條線或那根柱子用強調色，其餘灰。
- 直接在資料旁邊標數值與單位，少用圖例；軸線、格線淡到幾乎看不見或刪掉。
- 數字用等寬數字、靠右對齊、保留合理位數；不截斷數字與日期。
- 不只靠顏色區分（色盲、投影色偏）：加標籤、圖示或形狀。
- 資料來源與時間寫在圖下方註記；沒有資料就標「待補資料」，不畫假圖。
- 圖表不是必需品：沒有數據需求的簡報，證據改用引言、時間軸、真實畫面。
- 動畫只用在「依序揭示有意義」時（例如逐年長出、逐步加入對比）；跳頁時要直接顯示最終狀態。

## 6. 實作

- 優先用手寫 SVG 或 HTML/CSS 畫，清晰、可縮放、可離線；不引入大型圖表庫。
- 需要互動（切換資料集、hover 看數值）時，互動只補充細節，靜態狀態本身要能讀懂。
- 從 Mermaid、draw.io 匯入時，只取內容（節點、關係、分組、方向），重新排版，不沿用原工具的座標與配色；回報合併或刪掉了什麼。
