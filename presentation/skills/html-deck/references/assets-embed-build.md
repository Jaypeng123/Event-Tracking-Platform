# 素材、生成圖、Figma、嵌入網站、Demo 與單檔交付

## 1. 使用者提供的素材

- **每一份素材都要被用到**，或明確告訴使用者哪些沒用、為什麼（重複、解析度不足、與主張無關）。
- 文件、PDF、PPTX：先完整讀過，抽出主張、論點、數據、引言、圖片；文字要濃縮成投影片語言，使用者要求保留原文時才照抄。
- PPTX：取封面主色、字體、Logo、圖片；母片的版面不必照搬。
- 網頁：取真實文案與畫面截圖，不從網址推測內容。

## 2. 截圖與圖片處理

- 裁掉瀏覽器網址列、分頁列、作業系統選單列、桌面背景與空白邊；裁完的空間拿來放標題或說明。
- 轉 webp（品質 82–88），長邊 ≤ 2400px；檔名語意化（`checkout-error-state.webp`）。
  ```bash
  python3 -c "from PIL import Image; im=Image.open('in.png'); im.crop((0,88,im.width,im.height)).save('assets/x.webp','WEBP',quality=85)"
  ```
- 截圖太小或字看不清：用 HTML 重建那塊介面，或改成局部特寫，不硬塞整張。
- 同類圖片用一致的比例與外框；`alt` 寫內容，純裝飾用 `alt=""`。

## 3. 從 Figma 取素材（有 Figma MCP 時）

- 網址解析：`figma.com/design/:fileKey/...?node-id=1-2` → nodeId `1:2`；`/slides/` 是 Figma Slides，`/board/` 是 FigJam。
- 先讀結構（頁面與 frame 清單），再對**單一 frame 或區塊**截圖，不整頁截；預設截圖解析度偏低，簡報用要指定 2 倍。
- 網路擋下載時，用截圖工具的 base64 回應存檔。
- 需要真實內容（頁面名稱、元件文字、色票、字級）時從 Figma 讀取，不自己編。
- 要寫回 Figma（例如輸出 Figma Slides）時，依 figma-use 規則：小步執行、每步回傳節點 ID、先載入字體、顏色用 0–1、失敗就停下讀錯誤。

## 4. 用 HTML 重建介面（取代模糊截圖或示意）

從截圖或 frame 依序抽取：文字原文 → 字級、字重、行數 → 間距（標題到內文、元件間距、內距）→ 按鈕尺寸與層級 → 色彩角色 → 圓角 → 圖片處理。

不清楚時依序保留：可見的視覺語言 → 版面與間距邏輯 → 元件類型 → 氛圍；仍不確定就取得更清楚的局部圖，最後才選最容易實作的忠實版本。不要簡化成通用模板、不要壓縮間距。做完截圖和原圖逐區比對。

講產品或設計時，補上非理想狀態（空狀態、載入、錯誤、權限不足、極長文字）常是最有說服力的一頁。

**手機畫面**：以 390px 寬為基準重建，左右 20px 邊距、內文 ≥ 15–16px、觸控目標 ≥ 44px；iOS 字級 34/28/22/20/17/15/13/12，Material 字級 57/45/36/32/28/24/22/16/14/12/11。放進簡報時用一致的簡潔裝置框，同一份簡報同比例、四周留白均等。

## 5. AI 生成素材（選用）

**圖片**
- 同一份簡報用同一段**風格前言**，每次生成原樣附上，讓所有圖像像同一組拍攝。
- 用完整句子描述場景，寫清楚主體、材質、光線（柔光、逆光、陰天漫射）、鏡頭（50mm、廣角、微距）、構圖（三分法、俯視、留白位置）。
- 要求在標題位置留空：例如「左上三分之一保持乾淨的單色背景」。
- **不要讓圖片裡出現文字**，字一律用 HTML。
- 輸出 16:9，至少 3200×1800 給高解析螢幕；需要分層時去背做前景，與背景分開。
- 修改既有圖片時說清楚哪些要保留（構圖、主體、光線），只改要改的地方。
- 每張都要看過再用，不好就重生，不要直接上。

**影片**
- 5–8 秒、靜音、可循環；寫清楚「鏡頭固定」「除了 X 沒有其他動作」「無字幕」。
- before/after 可用首尾影格內插做轉場。
- 嵌入用 `<video muted loop playsinline poster="...">`，有暫停方法；單檔交付注意大小。

**版面參考圖**：需要先探索視覺方向時，可以每頁生成一張 16:9 參考圖給使用者挑，選定後再用 HTML 實作；參考圖裡的字只是示意。

**生成式背景**：用 canvas 或 p5 時固定 seed、配色取自 tokens、低對比、非作用頁暫停。

**動態圖解**：優先用 CSS／SVG；真的需要 Lottie 時，單檔交付要內嵌播放器，並檢查第 0 格、中間、最後一格。

所有素材下載到本機再內嵌，不要熱連結外部網址。

## 6. 嵌入線上網站

- iframe 全螢幕覆蓋該頁（不放在舞台內縮放），提供：重新整理、新分頁開啟、載入中與「載入太慢」提示（約 9 秒）。
- **只在前後一頁時才載入**，避免開場就佔頻寬。
- 事先告知限制：網站的 `X-Frame-Options`／CSP `frame-ancestors` 會拒絕嵌入；需要登入或第三方 cookie 的網站在 iframe 裡常失敗；現場網路可能不穩。
- 對策：做離線 Demo，線上網址當備案。

## 7. 離線 Demo（真的前端＋假 API）

適用：產品需要登入、會呼叫付費或不穩定的 API、現場可能沒網路。

1. 用打包工具（如 Vite）編譯產品真實的頁面元件與樣式；框架專屬的部分（伺服器端、路由）替換成最小可用版本。
2. 寫 mock 層攔截 `fetch`：每個 API 路徑回傳固定資料，加 300–1200ms 延遲讓載入狀態看得到；錯誤情境也做一份。
3. 資料盡量取自真實來源；若是假資料，在 Demo 或備註標明。
4. 需要預填的欄位用建置時的轉換或初始狀態設定，不改產品原始碼。
5. `file://` 會擋 `type="module"` 腳本：建置後把 JS／CSS 內嵌進 HTML。
6. 用 Playwright 跑一次完整流程並截圖；再用最壞資料（很長的名稱、0 筆、1 筆、大量資料）試一次。

## 8. 單一檔案交付

- `scripts/inline-icons.cjs deck.html`：把用到的 Lucide 圖示內嵌（換其他圖示庫時照同樣原則處理）。
- `scripts/build_standalone.py deck.html standalone.html [--demo demo/index.html]`：圖片轉 data URI；Demo 存成 `window.__DEMO_HTML__`，用 `iframe.srcdoc` 載入。
- 字體：系統字免處理；自訂 Latin 字 subset 後 base64 內嵌；中文字體太大不整包內嵌。
- 交付前斷網開一次單檔版。一般 5–15MB 可接受，超過 25MB 檢查未壓縮的 png 或影片。

## 9. 延伸成作品集長頁

簡報要轉成作品集時，另做一頁長捲動案例，而不是把簡報拉長：
摘要（TL;DR）→ 背景 → 定位 → 解法（嵌入 Demo，延遲載入）→ 關鍵決策（每個：問題／決策／結果）→ 過程 → 成果 → 反思。
- 側邊目錄＋閱讀進度＋捲動揭示（內容預設可見，動畫只是加強）。
- 沒有量化成果就只寫質性成果。
- 檢查 320／375／390／768px：`overflow-x: clip`、表格包可橫向捲動的容器、`min-width:0`、長字 `overflow-wrap:anywhere`，沒有水平溢出。
